# EDB 電子簽核系統分析

來源：`EDB.xml`（Magic xpa 3.3，專案名稱 `edb`）。

```
python magic_dump.py EDB.xml        # 程式清單
python magic_dump.py EDB.xml 7      # 展開「表單送簽(正本)」
```

## 這個專案是什麼

EDB 是一套**通用的電子表單簽核引擎**。它本身不處理業務資料，而是讓訂單、採購、HR 等各系統的表單接進來送簽：

- 每種表單在「A20元件註冊」登記一筆，表單代碼就是單號的前 3 碼。
- 簽核流程依「A20元件流程」的設定自動產生，可以依職位、部門、指定人員或表單欄位條件決定簽核人。
- 簽核時用 `Call By Name 'Modify'&表單代碼` 回頭呼叫該業務系統的表單程式，
  所以各業務系統的 `.ecf` 元件必須提供對應名稱的程式。

它和 `Files` 連到**同一個 Oracle 資料庫**（EDB 裡的資料來源名稱叫 `Master`），
`A01`、`A30`、`A40`、`A50`、`A60_7`、`A60_8`、`FILU001` 這 7 個資料表兩邊都有定義。

## 送簽流程（程式 #7 表單送簽(正本)）

輸入：單據流水號、表單代碼（沒給就取單號前 3 碼）、程式指定的簽核人員清單。

1. 讀取單據屬性（A01）、申請人（ViewOfEmp）、表單的元件註冊資料（A20）。
   表單代碼沒註冊就回傳錯誤訊息。
2. 如果開單人和申請人不同，通知申請人「代開單據通知」。
3. **免送簽核**的表單：直接把狀態設為結案 `E`，必要時設定核銷人員。
4. 其他表單：讀取 A20元件流程（A20_1）中該表單、該公司的每一個流程節點，逐一判斷：
   - 節點有**條件**（條件欄位＋條件式＋條件內容）時，用 `VarCurrN` 取表單上該欄位的值來比較，
     不符合就跳過。
   - **會簽**節點：建立會簽主項。
   - **指定欄位**：簽核人員取自表單上的某個欄位。
   - **指定人員**：`#` 代表由呼叫端程式傳入的人員清單，否則是固定人員。
   - 都沒有時，依**職位**找人：申請部門（或限定部門）裡擔任該職稱的人；
     若該員工有代理人（`REPLACEBY`），改由代理人簽。
   - 「申請人免簽」勾選時，簽核人是申請人本人就跳過。
   - 每產生一個節點，就寫一筆 A01_2 單據流程，簽核結果 `0`，並把單據狀態設為簽核中 `I`。
5. 清理：刪除沒有簽核人員的節點；「同人合併」時，同一個人重複出現的節點改為免簽。
6. 寫入活動記錄 `Open`。
7. 完全沒有產生流程時回傳「送簽失敗：尚未設定流程」。

退回與取回（#14 簽退取回、#17 退回草稿）會刪除該單的所有 A01_2 流程，並把狀態改回草稿 `0`；
作廢（#15）把狀態設為 `A`。

## 轉換時要注意

- **任務模式隱含刪除**：像「刪除沒有人員流程」這類子任務只有 Range 條件、沒有任何邏輯，
  實際行為來自任務的 Initial Mode = Delete，會刪除所有符合條件的記錄。`magic_dump.py` 會標示 `Mode=Delete`。
- **`VarCurrN` 動態取值**：條件判斷依設定檔裡的欄位名稱，取目前表單上的變數值。
  Python 版要改成由呼叫端傳入表單資料（dict），再依欄位名稱取值。
- **`Call By Name`**：依表單代碼呼叫其他系統的程式。Python 版可改成「表單代碼 → 處理函數」的註冊表。
- **SQL 用字串組合參數**：Magic SQL 的 `:1` 是直接把文字代換進 SQL，程式裡還自己加單引號
  （例如 `ASCIIChr(39)&Trim(E)&ASCIIChr(39)`），有 SQL injection 風險。Python 版一律改用參數化查詢。
- **呼叫 Windows DLL**：#4、#123 用 `OLE32.CoCreateGuid` 產生 GUID，Python 用 `uuid.uuid4()` 取代。
- **開啟本機程式**：多處用 `explorer`、`excel` 開檔案，網頁版要改成下載或線上預覽。

## 和 repo 裡現有文件管理系統的比較

現有 Flask 系統（`app.py`、`schema.sql`）的簽核是**固定人員**的範本：`workflow_templates` → `workflow_template_steps`，
每一步指定一個使用者。EDB 的規則比較完整：

| 功能 | 現有 Flask 系統 | EDB |
|---|---|---|
| 依職位＋部門自動找簽核人 | 無 | 有 |
| 代理人 | 無 | 有（`REPLACEBY`、A60代理人） |
| 依表單欄位條件決定要不要簽（例如金額 > 10 萬） | 無 | 有 |
| 會簽／並簽 | 無 | 有（A20元件階層的簽法） |
| 加簽、副本、受文者 | 無 | 有 |
| 同人合併、申請人免簽 | 無 | 有 |
| 退回、取回、作廢 | 有退回 | 有 |

如果目標是把 EDB 轉到這個 Flask 系統，建議把 EDB 的「流程產生規則」轉成獨立的 Python 模組，
由 Flask 的送簽功能呼叫，資料表沿用 `schema/postgresql.sql` 裡的 `a01`、`a01_2`、`a20`、`a20_1` 等。
